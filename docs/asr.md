# Khmer ASR extension

This document describes the speech-recognition extension built on top of the
Khmer Transliteration Keyboard. The current experiment uses a pretrained
XLS-R/Wav2Vec2 CTC checkpoint and fine-tunes it for Khmer speech. It does not
train a model from scratch.

## Current experiment

- Dataset: `Digital-Divide-Data/khmer-speech-dataset`
- Model: `vitouphy/wav2vec2-xls-r-300m-khmer`
- Audio target: mono, 16 kHz WAV
- Pilot: 1,000 selected rows, split into 793 training, 81 validation, and 126 test rows
- Split policy: complete speaker groups are kept in one split to reduce speaker leakage
- Test policy: the test split is not passed to `Trainer`; it is used only for final evaluation

The older 300-row pilot in `data/voice/` remains as a small local manifest. The
1,000-row manifests are generated/materialized in Colab or Google Drive and are
ignored by Git through `data/voice_1000/`.

## Repository structure

```text
khmer_transliteration/
  asr_audio.py          # WAV decoding and 16 kHz resampling
  asr_data.py           # manifest reading and streamed HF audio replay
  asr_inference.py      # clean tokenizer, model loading, and lazy web inference service
  asr_metrics.py        # CER, WER, sentence accuracy, latency metrics
  asr_text.py           # shared transcript normalization
  romanization.py       # dictionary-backed canonical Khmer -> Romanized output
scripts/
  inspect_asr_dataset.py
  build_asr_manifest.py
  validate_asr_manifest.py
  run_asr_baseline.py
  finetune_asr.py
notebooks/
  prepare_dataset.ipynb
  asr_baseline.ipynb
  finetune_asr.ipynb
```

The scripts reuse the package modules. They should not import helper functions
from another command-line script.

## Environment setup

The normal keyboard environment and the ASR environment are intentionally
separate:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -r requirements-asr.txt
```

PyTorch is not pinned in `requirements-asr.txt` because the correct build
depends on the machine and CUDA runtime. Colab already provides a compatible
PyTorch build. For a local GPU/CPU installation, use the command generated by
the [official PyTorch installation selector](https://pytorch.org/get-started/locally/).

## Dataset workflow

Inspect a small streamed sample without saving audio:

```powershell
python scripts/inspect_asr_dataset.py --max-rows 300
```

Build the pilot manifests. In PowerShell, use one line or the PowerShell
backtick for continuation; a Unix backslash is not a PowerShell continuation
character:

```powershell
python scripts/build_asr_manifest.py --target-rows 1000 --scan-rows 5000 --shuffle-buffer 1000 --output-dir data/voice_1000
```

Validate the deterministic replay and WAV headers:

```powershell
python scripts/validate_asr_manifest.py --manifest-dir data/voice_1000 --output data/voice_1000/manifest_validation.json
```

The CSV manifests store metadata and source row indexes, not all audio bytes.
When training, `finetune_asr.py` replays the same deterministic stream and
materializes only the selected WAV files.

## Baseline and fine-tuning

Run a small baseline smoke test first:

```powershell
python scripts/run_asr_baseline.py --manifest-dir data/voice_1000 --split test --max-samples 3 --output reports/asr/baseline_smoke_test.json
```

Baseline evaluation now caches selected audio in
`data/voice_1000/audio_cache/` and prints stream/inference progress. The first
run still needs to replay the Hugging Face stream; later runs load the cached
WAV files locally. Use `--no-audio-cache` only when a fresh remote replay is
needed.

Materialize and train in a GPU notebook/runtime:

```powershell
python scripts/finetune_asr.py --stage materialize --manifest-dir data/voice_1000 --materialized-dir data/voice_1000/materialized_training
python scripts/finetune_asr.py --stage validate-tokenizer --model vitouphy/wav2vec2-xls-r-300m-khmer
python scripts/finetune_asr.py --stage smoke --materialized-dir data/voice_1000/materialized_training --output-dir models/khmer_xlsr_ddd_1000_clean_smoke
python scripts/finetune_asr.py --stage full --materialized-dir data/voice_1000/materialized_training --output-dir models/khmer_xlsr_ddd_1000_clean
```

The fine-tuning script rebuilds the tokenizer directly from `vocab.json`,
checks that its full length matches the model's CTC output vocabulary, and
encodes labels with `add_special_tokens=False`. The `|` word-delimiter token
is checked before training. This prevents accidental BOS/EOS or duplicated
special-token entries from becoming training labels. The corrected checkpoint
uses the `_clean` name so the earlier pilot remains available for comparison.

In Colab, the manifests and checkpoints are copied to Google Drive so they
survive runtime shutdown. The local model directory is intentionally ignored
by Git because the checkpoint is approximately 1.18 GiB. Keep the model files
needed by `from_pretrained()` together: `model.safetensors`, `config.json`,
processor/tokenizer JSON files, and any saved training summary/checkpoints.

The application automatically prefers `models/khmer_xlsr_ddd_1000_clean/` and
falls back to the earlier `models/khmer_xlsr_ddd_1000/` if the corrected model
has not been copied locally. Set `KHMER_ASR_MODEL_PATH` to use another local
checkpoint, or remove both local folders to fall back to the pretrained
Hugging Face model.

## Evaluation

Every reference transcript and prediction is normalized with the same NFC,
trim, and whitespace-collapse procedure before comparison. Reports include:

- CER: character error rate
- WER: word error rate
- sentence accuracy: exact normalized sentence matches
- mean/median/p95 model latency
- real-time factor when clip duration is available
- `[UNK]`, missing-space, and subscript-reference diagnostics

The current 1,000-row Colab run showed an improvement over the pretrained
baseline on the held-out test rows, but the pilot is too small for a final
claim. Re-run evaluation after every model/data change and keep the test split
fixed.

## Dual-script output

The ASR prediction is Khmer script. The current Romanized Khmer output is a
transparent dictionary-backed reverse lookup using `data/all_words.csv`: for a
known Khmer token it selects the highest-frequency existing romanization, and
it preserves unknown text. Khmer-to-Romanized text is not mathematically
unique, so this is a baseline integration rather than a fully trained
romanization model.

For the proposal, evaluate Romanized output separately with a manually
verified subset containing Khmer references and approved Romanized labels.
Do not report Romanization accuracy from automatically generated labels.

## Web API and UI

Start the application as usual:

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

The existing keyboard endpoints remain unchanged. The ASR extension adds:

- `GET /api/asr/status` — reports whether the model has been loaded
- `POST /api/asr/warmup` — explicitly loads the model before recording
- `POST /api/asr` — accepts a WAV request body and returns Khmer text,
  Romanized text, model/device information, and inference latency

The browser UI automatically requests model warmup when the page loads, then
records microphone input, converts it to mono 16 kHz WAV, and displays both
outputs. WAV upload is supported; arbitrary WebM/MP3 conversion is
intentionally outside the current server dependencies.
